# Дизайн: миграция IntentReactor на Spring Boot 4.0.8 / Spring AI 2.0.1 / Jackson 3

Дата: 2026-09-02. Ветка: `migration/spring-ai-2.0`. Статус: утверждён владельцем.

## 1. Контекст и цель

Много-модульный Maven-фреймворк `com.intentreactor:*` (12 модулей, Java 17) собран на
Spring Boot 3.5.13 + Spring AI 1.1.4 + Jackson 2.17 (через BOM Boot). Цель — миграция
**всех модулей** на Spring AI 2.0.1, что требует Spring Boot 4.0.x (выбран последний в
ветке — 4.0.8) и Jackson 3 (`tools.jackson`, управляется Boot BOM, 3.1.5). Baseline языка
поднимается с Java 17 до Java 21 (байткод target 21). Обратная совместимость с Boot 3.5
не требуется. Сборка/тесты выполняются локально на JDK 25 (машина владельца) с
`source/target=21`; CI — на JDK 21.

Публичный API фреймворка (`com.intentreactor.*`, артефакты, свойства `intent-reactor.*`)
по именам и семантике **не меняется**. Внешне меняются только требования: Java 21+,
Spring Boot 4.0+, Spring AI 2.0.x.

## 3. Карта разлома (подтверждено исследованием)

### 3.1 Spring AI поверхность — узкая, в 2.0 сохранена

Все вызовы LLM в фреймворке: `chatClient.prompt(new Prompt(messages)).call().content()`
(~40 сайтов: core — 7 файлов, strategies — 15, tool-dynamic, плюс `prompt().user()` в
`MessageCompressor`/`DynamicScriptTool`). Пакеты `org.springframework.ai.chat.messages.*`,
`org.springframework.ai.chat.prompt.Prompt`, `ChatClient`, `EmbeddingModel.embed(String)`
(rag) и MCP-классы (`org.springframework.ai.mcp.SyncMcpToolCallbackProvider`,
`McpToolsChangedEvent`, `org.springframework.ai.tool.ToolCallback`,
`ToolDefinition`/`DefaultToolDefinition`) в Spring AI 2.0 существуют с теми же FQN.
Документированные поломки 2.0 (удаление внутреннего tool-цикла в `ChatModel`,
`FunctionCallback`, options-immutability, advisor-переименования, свойства `.options`,
MCP SDK 1.1→2.0 и перенос Spring-транспортов в `org.springframework.ai`) **этот код не
затрагивают** — фреймворк не использует нативный tool-calling, options, advisors, streaming.

Открытые вопросы решаются компилятором против реальных jar (см. §5): сигнатура
`ChatClient.prompt(Prompt)`, наличие `DefaultToolDefinition` (возможно, только
`ToolDefinition.builder()`), `SyncMcpToolCallbackProvider.builder().mcpClients(...)`,
nested-типы `ChatClient.ChatClientRequestSpec/CallResponseSpec` в тестах.

### 3.2 Jackson 3 — основной объём работы

- api: аннотации `@JsonProperty/@JsonCreator/@JsonDeserialize/@JsonTypeInfo/@JsonSubTypes/@JsonIgnore`
  (→ `tools.jackson.annotation.*`), кастомный `StringOrArrayDeserializer`
  (→ `tools.jackson.databind.deser.std.StdDeserializer`, `tools.jackson.core.JsonParser/JsonToken`,
  `tools.jackson.databind.DeserializationContext`).
- core: `ObjectMapper`, `JavaTimeModule` → `tools.jackson.datatype.jsr310`, `SimpleModule`;
  бин `intentReactorObjectMapper` (`@ConditionalOnMissingBean(ObjectMapper.class)`) — тип
  становится tools.jackson (Bean Boot 4 уже такой).
- session-jdbc/jpa, tool-dynamic (`JdbcScriptRepository`), sand-train — собственные
  `new ObjectMapper().registerModule(new JavaTimeModule())`.
- strategies (11 планировщиков), mcp-client/mcp-server адаптеры, core-парсеры LLM:
  `TypeReference` → `tools.jackson.core.type.TypeReference`, `readValue/convertValue/writeValueAsString`.
- Тесты: ~10 классов с `new ObjectMapper()`.

## 4. Стратегия миграции

Один проход снизу вверх по графу модулей, каждая стадия завершается компиляцией+тестами
этого модуля:

1. **pom-слой**: родитель (Java 21, Boot 4.0.8, AI 2.0.1, lombok, удалить `jackson.version`),
   координаты jackson и mcp-spring-webmvc по всем модулям; `spring-boot-configuration-processor`
   и стартеры — только если Boot 4 их переименовал (проверить: `spring-boot-starter-web`,
   `-data-jpa`, `-jdbc`, `-autoconfigure`, `-configuration-processor`; при наличии rename —
   заменить координаты).
2. **api** — Jackson 3 импорты/аннотации/десериализатор; тесты api.
3. **core** — Jackson 3, вызовы Spring AI (проверка §5), auto-config, тесты core.
4. **session-jdbc, session-jpa, tool-commons, spring-boot-starter** — Jackson/координаты.
5. **tool-dynamic, rag, sand-train, strategies** — Jackson 3 + при необходимости Spring AI.
6. **mcp-client, mcp-server** — Jackson 3 + адаптеры ToolCallback/ToolDefinition/MCP SDK;
   проверка `JacksonMcpJsonMapper` (MCP SDK 2.0 на Jackson 3).
7. **Тесты реактора**: полный `mvn test` (33+ тестов), правка mock-цепочек ChatClient под
   типы 2.0 (см. §5.4).
8. **CI и документация**: `.github/workflows/release.yml` (Java 21), AGENTS.md (JDK 21),
   README.md + README-ru.md, docs + docs-ru (версии Boot/AI/Java, таблицы требований),
   где встречается «3.5»/«17».

## 5. Верификация и открытые точки

### 5.1 Базовые команды
- Один модуль/тест: `mvn -pl <module> -am -Dtest=ClassName test` (JDK 25 локально).
- Полный реактор: `mvn test`.

### 5.2 Проверки по факту (компилятор/javap по jar 2.0.1 — источник истины)
1. `ChatClient.prompt(Prompt)` / `prompt(List<Message>)` сигнатуры и `Prompt(List<Message>)` ctor.
2. `UserMessage(String)`, `SystemMessage(String)`, `AssistantMessage(String)` — не менялись (проверить).
3. `DefaultToolDefinition.builder()...inputSchema(String)` vs `ToolDefinition.builder()` в mcp-server.
4. `SyncMcpToolCallbackProvider.builder().mcpClients(List<McpSyncClient>)`, `getToolCallbacks()`.
5. `ChatClient.ChatClientRequestSpec`/`CallResponseSpec` (nested) в тестах; возврат `call()`.
6. MCP SDK: `JacksonMcpJsonMapper`/`StdioClientTransport` ctor с tools.jackson ObjectMapper;
   типы `io.modelcontextprotocol.spec.McpSchema` (@ConditionalOnClass) и `McpSyncClient`.
7. Boot 4: имена стартеров; бин `ObjectMapper` (tools.jackson) в авто-конфигурации Boot.
8. lombok на javac 25: версия из BOM Boot 4; если javac жалуется — поднять lombok.version.

### 5.3 Регрессионные риски
- Аннотации Jackson 3 и семантика `@JsonCreator/@JsonDeserialize(as=...)` — покрыто
  тестами session-хранилищ и тестами десериализации LLM-ответов.
- `@JsonTypeInfo` полиморфизм `SearchTree` — покрыто round-trip в LATS/сессионных тестах.
- Сохранённые ранее JSON-сессии (файлы/БД) после перехода на Jackson 3 несовместимы
  (другой пакет аннотаций) — документируется в README/docs как breaking change для
  хранилищ (минорный нюанс: данные воссоздаются перезапуском; для jdbc/jpa — формат JSON
  в колонке меняется, старые строки прочитать нельзя).
- README-ru/README и docs-ru/docs — обязательная зеркальная правка (конвенция проекта).
- Промпты/форматы LLM не меняются.

### 5.4 Тесты
- Уже существующие (33 файла) должны пройти без переписывания логики; правки касаются
  только импортов Jackson и, при необходимости, типов mock-цепочек ChatClient.
- Новых тестов миграция не требует (чистая миграция без изменения поведения);
  добавлять только если компиляция/поведение 2.0 вскроет дефект.

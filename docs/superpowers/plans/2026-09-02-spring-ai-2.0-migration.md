# IntentReactor: миграция на Spring Boot 4.0.8 / Spring AI 2.0.1 / Jackson 3 — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Перевести все 12 модулей IntentReactor с Java 17 / Spring Boot 3.5.13 / Spring AI 1.1.4 / Jackson 2 на Java 21 (bytecode) / Spring Boot 4.0.8 / Spring AI 2.0.1 / Jackson 3 (`tools.jackson`) без изменения публичного API и поведения.

**Architecture:** Чистая техническая миграция без смены логики. Spring AI-поверхность фреймворка узкая (`ChatClient.prompt(Prompt).call().content()`, пакеты `chat.messages`, `Prompt`, `EmbeddingModel.embed(String)`, MCP-классы) и в 2.0 сохранена с теми же FQN — основной объём составляет механическая замена импортов/координат Jackson 2 → 3 и точечная адаптация MCP-обвязки под MCP SDK 2.0 (переименован пакет `JacksonMcpJsonMapper` → `io.modelcontextprotocol.json.jackson3`). Работа идёт снизу вверх по графу модулей: каждый модуль компилируется и проходит свои тесты до перехода к следующему.

**Tech Stack:** Maven (без wrapper), JDK 25 локально (сборка с `source/target=21`), Spring Boot 4.0.8 BOM, Spring AI 2.0.1 BOM, Jackson 3 из BOM Boot (`tools.jackson` 3.1.5), lombok 1.18.46, Git Bash на Windows (CRLF working copy; коммиты нормализуются в LF за счёт `core.autocrlf=true`).

**Spec:** `docs/superpowers/specs/2026-09-02-spring-ai-2.0-migration-design.md` (читать вместе с планом; план аргументирует от spec).

## Global Constraints

- Версии (единственный источник правды — spec §2): Java `source/target` = **21**; `spring-boot.version` = **4.0.8**; `spring-ai.version` = **2.0.1**; lombok = **1.18.46**; свойство `jackson.version` в родителе **удалить** (Jackson 3 версионируется BOM Boot 4).
- Координаты Jackson 3: `tools.jackson.core:jackson-databind`, `tools.jackson.datatype:jackson-datatype-jsr310` (без `<version>` — BOM Boot 4). Никаких ссылок на `com.fasterxml.jackson` после миграции (кроме, если компилятор докажет обратное, — тогда стоп и вопрос владельцу).
- Публичный API фреймворка (`com.intentreactor.*`, свойства `intent-reactor.*`, артефакты, версия 0.1.16) **не меняется**. Логика, промпты, форматы LLM-контракта — **не меняются**.
- **ImportMap Jackson 2 → 3** (применять во всех файлах main/test всех модулей):
  `com.fasterxml.jackson.databind.ObjectMapper` → `tools.jackson.databind.ObjectMapper`; `com.fasterxml.jackson.databind.json.JsonMapper` → `tools.jackson.databind.json.JsonMapper`; `com.fasterxml.jackson.datatype.jsr310.JavaTimeModule` → `tools.jackson.datatype.jsr310.JavaTimeModule`; `com.fasterxml.jackson.core.type.TypeReference` → `tools.jackson.core.type.TypeReference`; `com.fasterxml.jackson.core.JsonParser` → `tools.jackson.core.JsonParser`; `com.fasterxml.jackson.core.JsonToken` → `tools.jackson.core.JsonToken`; `com.fasterxml.jackson.databind.DeserializationContext` → `tools.jackson.databind.DeserializationContext`; `com.fasterxml.jackson.databind.deser.std.StdDeserializer` → `tools.jackson.databind.deser.std.StdDeserializer`; `com.fasterxml.jackson.databind.module.SimpleModule` → `tools.jackson.databind.module.SimpleModule`; `com.fasterxml.jackson.annotation.*` → `tools.jackson.annotation.*` (`JsonProperty`, `JsonCreator`, `JsonDeserialize`, `JsonIgnore`, `JsonTypeInfo`, `JsonSubTypes`); `com.fasterxml.jackson.core.JsonNode/JsonGenerator/…` (если встретится) → `tools.jackson.core.*`.
- Механика правок: файлы менять инструментом edit (точные замены строк), не переписывая файл целиком; CRLF рабочей копии сохранять (git нормализует при коммите сам).
- Рабочая ветка `migration/spring-ai-2.0` (создана, spec закоммичен). Git identity настроен локально (Лушин Владимир <lushago123@gmail.com>).
- Команды выполняются из корня реактора. Названия тестов в командах `-Dtest=` писать без `Test`-суффикса не нужно — полное имя класса как есть.
- Все «ожидаемые ошибки компиляции» ниже — это норма миграции: починка заключается в следовании инструкциям шага, а не в изменении архитектуры. Если компилятор показывает API, отсутствующий в списках ниже, — зафиксировать фактическую сигнатуру (javap из jar или javadoc) и применить минимальную адаптацию; при сомнении в выборе — остановиться и спросить владельца.
